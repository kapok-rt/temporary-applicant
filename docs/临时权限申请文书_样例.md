## 二、这份文书为什么应当"批准"

游戏内判定按 **Captain 临时指令 → 硬规则 → 阅读判断** 三级优先级执行，
这份文书的检查过程如下：

| 检查项 | 结论 |
|---|---|
| R1 是否签名 | 已签署，通过 |
| R2 武器类是否附 HoS 预盖章 | 非武器类，不适用 |
| R3 安全记录是否含"可疑"标注 | 无，通过 |
| 软线索：理由与职务是否相符 | 实习医师申请药品柜权限，与职务相符 |
| 软线索：请求范围是否越权 | 只申请药品柜，未扩权，范围克制 |
| 软线索：记录细节是否对得上 | 在册 47 天，且有按期归还记录 |

→ **判定结果：批准（消耗印章耐久 1 点，信任值 +1）**

作为对照，同批次另外两份文书不成立：

- **A-102（武器许可）**：安全部战术警员申请配发能量手枪，签名齐全，但部门章是
  "安全部 · 值班章（无 HoS 预盖章）"。触发硬规则 R2 → 驳回。
- **A-103（部门调动）**：工程部初级技师的调动申请，理由充分、部门章清晰，
  但签核栏空白。触发硬规则 R1 → 驳回。

## 三、字段对照（策划/文案改内容时看这里）

上表内容对应 `data/applications.json` 中的一条记录，改 JSON 即可增删文书，
不需要改任何代码（需求案 FR-09）：

```json
{
  "id": "A-101",
  "batch": 1,
  "doc_type": "临时权限申请书",
  "form_no": "NT-HOP-0117",
  "applicant": "Kira Voss",
  "role": "医疗部 · 实习医师",
  "request": "申请开通医疗部药品柜（Pharmacy）的临时开启权限，有效期至本值班周期结束，到期自动失效。",
  "reason": "本班次值班医师仅我一人在岗，而急救取药流程要求双人在场核验，当前流程无法闭合。",
  "signed": true,
  "dept_stamp": "医疗部 · CMO 章（清晰）",
  "security_note": "入职 47 天，无违规记录。上一份临时权限已按期归还，归还时间早于截止 6 小时。",
  "ideal_action": "approve",
  "error_type": "",
  "tags": ["教学", "常规", "医疗"]
}
```

几个容易踩的点：

- `tags` 里出现 `武器` 会启用硬规则 R2，此时必须同时写 `hos_prestamp`（true/false）。
- `tags` 里出现 `跨部门`、`D级` 会被 Captain 临时指令接管，`ideal_action` 必须与指令结论一致，
  否则 `tests/rules_test.gd` 会报错。
- `security_note` 里只要出现"可疑"两个字就会触发 R3（转交），要慎用。
- `error_type` 是给事件系统统计错判用的键，必须能在 `data/events.json` 里找到对应事件，
  或留空（留空时按 `mishandled` 统计）。
